# opencode-brief

OpenCode TUI plugin: `/brief` opens an executive summary of the current session in a dialog.

Same mechanism as the built-in `/btw` — one model call that reads the session context and returns
transient text — but with the brief format baked in, so it never lands in the transcript.

## Install

Add the package path to `~/.config/opencode/cli.json`:

```json
{
  "plugins": [{ "package": "/path/to/opencode-brief" }]
}
```

Restart the TUI. Rollback is removing that entry.

## Use

```
/brief              # brief de la sesión
/brief deploy       # mismo brief, enfocado en un aspecto
```

- `c` copies the brief, `escape` closes the panel.
- The instructions come from `~/.config/opencode/skills/brief/SKILL.md` at call time, so editing the
  skill changes both this panel and the `/brief` chat command. A built-in fallback is used when the
  file is missing.

## Model

By default the brief is generated by the session's own model, through
`client.session.generate` — it sees the conversation natively, cannot call tools, and does not
mutate history.

To use a different model, set `model` in the plugin options (`provider/model` or
`provider/model#variant`):

```json
{
  "plugins": [
    {
      "package": "/path/to/opencode-brief",
      "options": { "model": "anthropic/claude-sonnet-4-5" }
    }
  ]
}
```

That switches to `client.generate.text`, which is stateless: the plugin serializes the transcript
(tail-capped at 40k characters) and sends it as prompt text. Costs more input tokens and loses
anything that never made it into the transcript.

## Why a dialog

A slash command submits its expanded template as a user prompt, so a 50-line command fills the
transcript. This plugin keeps the instruction out of the conversation and renders the result in a
dismissable panel instead.
